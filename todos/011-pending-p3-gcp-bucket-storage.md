# fix: Store raw master_material_map.json in GCP Bucket

**Status:** Pending
**Priority:** P3

## Context
Currently, `master_material_map.json` is generated by `source_data.py` on every CI run, but we explicitly do not commit it to avoid bloating the git history with noisy diffs. Because it is not committed, local development environments have a stale snapshot, and the CI run loses the previous state history.

## Proposed Architecture
We should migrate this data store to a Google Cloud Storage bucket:
1. In `deploy.yml`, authenticate to GCP and download the latest `master_material_map.json` from the bucket before running `source_data.py`.
2. Let `source_data.py` update the map with new materials.
3. After the run, upload the updated `master_material_map.json` back to the GCP bucket.
4. Update `source_data.py` to handle bucket fetching directly when run locally (if credentials are provided).

This maintains a single source of truth for the raw data while keeping the repository clean.
